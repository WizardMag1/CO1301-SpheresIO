1. Introduction 
This lab will introduce you to one of the most important concepts in game development. That topic 
is Finite State Machines (or FSMs for short). This lab is very important, as in games, everything can 
be considered an FSM. Try to understand the topic , and if you h ave any questions, please ask for 
help from your tutor. 
Terminology: 
Finite State Machines (FSMs)  are a fundamental concept in game development used to control 
the behaviour of game characters, objects, and systems. An FSM consists of a set of predefined 
states, transitions, and conditions that determine how an entity behaves and moves between 
different states. At any given moment, an entity can only be in one state, and transitions occur when 
specific conditions or events are triggered. For example, an enemy NPC might have states such as 
Idle, Patrol, Chase, Attack, and Death. The enemy may transition from Patrol to Chase when the 
player enters its detection range, and from Chase to Attack when the player is close enough. FSMs 
are widely used in game development for implementing Artificial Intelligence (AI), character 
animations, gameplay mechanics, user interfaces, and game logic . Their main advantages 
include simplicity, predictability, modularity, and ease of debugging, making them an essential tool 
for developing structured and responsive game systems.

8. The removal of a model means that it is destroyed. It is no longer possible to use the model 
since it no longer exists and, indeed, if you tried (for example) to move the model after removal, 
you would generate a real-time error.   
9. Although the model has been destroyed , the IModel* variable still exists. This is because the 
IModel* variable is a particular kind of variable called a pointer, which is declared using an 
asterisk (*). The pointer still exists, but the removal of the model means it no longer has 
anything to point at.  However, the IModel variable can be reused to point to a newly 
created model. For example, the  code below serves no real purpose , but it does show the 
process of removing a model and reusing its IModel* variable: 
IModel* sphere = sphereMesh->CreateModel( ); // declare variable and create model 
sphereMesh->RemoveModel( sphere ); // remove model 
sphere = sphereMesh->CreateModel( ); // create new model

3. Using Enums to Store Game State 
1. Booleans are useful in handling binary states, e.g., true or false, exists or does not exist, left or 
right, up or down, etc. For more complex situations, however, enumerations should be used.  
2. Enums offer several advantages, including improved readability because they state what they 
mean, and extensibility since you can easily add a new state as and when required. 
3. Let's add the ability to change the color of the sphere (by changing its skin) while using Enums
